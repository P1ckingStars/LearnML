## 1. Motivation

In Lecture 05a, we reduced type inference to constraint solving: given an unannotated term, we generate a set of equations between type expressions, and type reconstruction succeeds if and only if these equations have a simultaneous solution.

**Unification** is the algorithm that solves such equation systems. Given two type expressions $S$ and $T$, unification asks: does there exist a substitution $\sigma$ such that $\sigma(S) = \sigma(T)$? If so, it finds the most general such substitution.

Unification was introduced by Robinson (1965) as a subroutine for his resolution-based theorem prover, but its applications extend far beyond theorem proving: type inference (Hindley 1969, Milner 1978), logic programming (Prolog), term rewriting, automated theorem proving, and program analysis all rely on unification.

The beauty of unification lies in its universality: it is the canonical algorithm for "making things equal by instantiation." It is to equational reasoning what substitution is to variable binding---a fundamental operation that appears throughout computer science and logic.

### 1.1 Unification vs. Matching vs. Equality

Three related but distinct problems arise when comparing terms:

**Equality checking:** Given ground terms $S$ and $T$ (no variables), decide whether $S = T$. This is trivial---just compare structurally in $O(n)$ time.

**Matching (one-sided unification):** Given a pattern $S$ (with variables) and a ground term $T$ (no variables), find a substitution $\sigma$ such that $\sigma(S) = T$. Only the variables in $S$ may be instantiated; $T$ is fixed. Matching is decidable in linear time and always has a unique solution if one exists.

**Unification (two-sided):** Given terms $S$ and $T$ (both may contain variables), find a substitution $\sigma$ such that $\sigma(S) = \sigma(T)$. Variables on both sides may be instantiated. Unification is more general than matching: if $T$ is ground, unification reduces to matching.

Type inference requires full unification because both sides of the generated constraints may contain type variables.

### 1.2 Unification Beyond Type Inference

While our primary interest is type inference, unification plays a central role in many areas:

- **Logic programming (Prolog):** Resolution steps involve unifying the head of a clause with the current goal. Prolog's execution model is essentially a sequence of unifications.

- **Term rewriting:** Applying a rewrite rule $l \to r$ to a term $t$ at position $p$ requires matching $l$ against $t|_p$ (the subterm at position $p$). Narrowing, a combination of rewriting and unification, uses full unification.

- **Automated theorem proving:** Resolution, paramodulation, and superposition all use unification as a core subroutine.

- **Program analysis:** Abstract interpretation and points-to analysis sometimes use unification-based approaches for efficiency.

## 2. Core Theory

### 2.1 Formal Setup

We work in the setting of first-order terms over a signature, which generalizes the specific case of type expressions.

**Definition 2.1 (Signature).** A signature $\Sigma$ consists of:
- A countably infinite set $\mathcal{V}$ of variables $\{\alpha, \beta, \gamma, \alpha_1, \alpha_2, \ldots\}$.
- A finite or countable set of function symbols, each with a fixed arity: $f/n$ means $f$ takes $n$ arguments.

For type inference, the relevant signature includes:
- The binary constructor $\to$ (arity 2), written infix.
- Base type constants $\text{Int}$, $\text{Bool}$, $\text{Unit}$, etc. (arity 0).
- Parameterized type constructors: $\text{List}/1$, $\text{Pair}/2$, $\text{Option}/1$, etc.

**Definition 2.2 (Terms).** The set of terms $\mathcal{T}(\Sigma, \mathcal{V})$ over signature $\Sigma$ and variables $\mathcal{V}$ is defined inductively:
- If $\alpha \in \mathcal{V}$, then $\alpha \in \mathcal{T}(\Sigma, \mathcal{V})$.
- If $f \in \Sigma$ has arity $n$ and $t_1, \ldots, t_n \in \mathcal{T}(\Sigma, \mathcal{V})$, then $f(t_1, \ldots, t_n) \in \mathcal{T}(\Sigma, \mathcal{V})$.

For type expressions specifically:
- Variables: $\alpha, \beta, \gamma, \ldots$
- Arrow types: $\to(T_1, T_2)$, written $T_1 \to T_2$.
- Base types: $\text{Int}$, $\text{Bool}$ (arity 0).
- Parameterized types: $\text{List}(T)$ (arity 1), $\text{Pair}(T_1, T_2)$ (arity 2).

**Definition 2.3 (Size and Depth).** The size $|t|$ and depth $d(t)$ of a term are:

$$|\alpha| = 1, \quad d(\alpha) = 0$$

$$|f(t_1, \ldots, t_n)| = 1 + \sum_{i=1}^n |t_i|, \quad d(f(t_1, \ldots, t_n)) = 1 + \max_i d(t_i)$$

**Definition 2.4 (Substitution, recap).** A substitution $\sigma : \mathcal{V} \to \mathcal{T}(\Sigma, \mathcal{V})$ maps variables to terms, extended homomorphically:

$$\sigma(\alpha) = \begin{cases} t & \text{if } (\alpha \mapsto t) \in \sigma \\ \alpha & \text{otherwise} \end{cases}

$$

$$\sigma(f(t_1, \ldots, t_n)) = f(\sigma(t_1), \ldots, \sigma(t_n))$$

**Definition 2.5 (Domain and Range).** For a substitution $\sigma$:

$$\text{dom}(\sigma) = \{\alpha \in \mathcal{V} \mid \sigma(\alpha) \neq \alpha\}$$

$$\text{ran}(\sigma) = \bigcup_{\alpha \in \text{dom}(\sigma)} \text{FV}(\sigma(\alpha))$$

where $\text{FV}(t)$ denotes the set of variables occurring in $t$.

**Definition 2.6 (Idempotent Substitution).** A substitution $\sigma$ is idempotent if $\sigma \circ \sigma = \sigma$: applying it twice yields the same result as applying it once.

**Lemma 2.7.** A substitution $\sigma$ is idempotent if and only if $\text{dom}(\sigma) \cap \text{ran}(\sigma) = \emptyset$.

*Proof.* ($\Rightarrow$) Suppose $\alpha \in \text{dom}(\sigma) \cap \text{ran}(\sigma)$. Then $\sigma(\alpha) \neq \alpha$ and $\alpha$ occurs in $\sigma(\beta)$ for some $\beta \in \text{dom}(\sigma)$. Consider $\sigma(\sigma(\beta))$: since $\alpha$ occurs in $\sigma(\beta)$, applying $\sigma$ again replaces $\alpha$ by $\sigma(\alpha) \neq \alpha$, so $\sigma(\sigma(\beta)) \neq \sigma(\beta)$, contradicting idempotence.

($\Leftarrow$) If $\text{dom}(\sigma) \cap \text{ran}(\sigma) = \emptyset$, then for any term $t$, every variable in $\sigma(t)$ is either:
- A variable $\beta \notin \text{dom}(\sigma)$ that was already in $t$ (and is thus fixed by $\sigma$), or
- A variable in $\text{ran}(\sigma) \setminus \text{dom}(\sigma)$ that was introduced by $\sigma$ (and is also fixed by $\sigma$, since it is not in $\text{dom}(\sigma)$).

In either case, $\sigma(\sigma(t)) = \sigma(t)$. The formal proof is by structural induction on $t$:

Base case: $t = \alpha$. If $\alpha \in \text{dom}(\sigma)$, then $\sigma(\alpha) = T$ for some $T$ with $\text{FV}(T) \subseteq \text{ran}(\sigma)$. Since $\text{dom}(\sigma) \cap \text{ran}(\sigma) = \emptyset$, every variable in $T$ is outside $\text{dom}(\sigma)$, so $\sigma(T) = T = \sigma(\alpha)$. If $\alpha \notin \text{dom}(\sigma)$, then $\sigma(\alpha) = \alpha$ and $\sigma(\sigma(\alpha)) = \sigma(\alpha) = \alpha$.

Inductive case: $t = f(t_1, \ldots, t_n)$. $\sigma(\sigma(f(t_1, \ldots, t_n))) = \sigma(f(\sigma(t_1), \ldots, \sigma(t_n))) = f(\sigma(\sigma(t_1)), \ldots, \sigma(\sigma(t_n)))$. By the induction hypothesis, $\sigma(\sigma(t_i)) = \sigma(t_i)$ for each $i$. So $\sigma(\sigma(t)) = f(\sigma(t_1), \ldots, \sigma(t_n)) = \sigma(t)$. $\square$

### 2.2 The Unification Problem

**Definition 2.8 (Unification Problem).** A unification problem is a finite set of equations:

$$\mathcal{E} = \{S_1 \doteq T_1, \ldots, S_n \doteq T_n\}$$

where $S_i, T_i \in \mathcal{T}(\Sigma, \mathcal{V})$. We use $\doteq$ (rather than $=$) to distinguish syntactic equations-to-be-solved from semantic equality.

**Definition 2.9 (Unifier).** A substitution $\sigma$ is a unifier of the equation $S \doteq T$ if $\sigma(S) = \sigma(T)$ (syntactic equality after substitution). It is a unifier of a problem $\mathcal{E}$ if it unifies every equation in $\mathcal{E}$.

We write $\text{Unif}(\mathcal{E})$ for the set of all unifiers of $\mathcal{E}$.

**Definition 2.10 (Unifiable).** An equation $S \doteq T$ (or a problem $\mathcal{E}$) is unifiable if $\text{Unif}(\mathcal{E}) \neq \emptyset$.

**Definition 2.11 (Most General Unifier).** A unifier $\sigma$ of $\mathcal{E}$ is a most general unifier (MGU) if for every other unifier $\sigma'$ of $\mathcal{E}$, there exists a substitution $\delta$ such that $\sigma' = \delta \circ \sigma$.

In other words, every unifier factors through the MGU. The MGU commits to the minimum amount of instantiation necessary to make the terms equal.

**Example 2.12.** Consider $\mathcal{E} = \{\alpha \to \beta \doteq \text{Int} \to \gamma\}$.

- $\sigma_1 = [\alpha \mapsto \text{Int}, \beta \mapsto \gamma]$ is a unifier: $\sigma_1(\alpha \to \beta) = \text{Int} \to \gamma = \sigma_1(\text{Int} \to \gamma)$.
- $\sigma_2 = [\alpha \mapsto \text{Int}, \beta \mapsto \text{Bool}, \gamma \mapsto \text{Bool}]$ is also a unifier.
- $\sigma_1$ is more general: $\sigma_2 = [\gamma \mapsto \text{Bool}] \circ \sigma_1$.
- $\sigma_1$ is the MGU.

**Example 2.13.** Consider $\mathcal{E} = \{\alpha \doteq \alpha \to \beta\}$.

No unifier exists: any substitution for $\alpha$ produces a term strictly smaller than $\alpha \to \beta$ with the same substitution applied. This is the **occurs check** failure.

**Example 2.14.** Consider $\mathcal{E} = \{\text{Int} \doteq \text{Bool}\}$.

No unifier exists: $\text{Int}$ and $\text{Bool}$ are distinct constants (distinct function symbols of arity 0). This is a **clash** failure.

### 2.3 Robinson's Unification Algorithm

We present Robinson's algorithm (1965) in its recursive formulation, then prove its correctness properties.

**Algorithm 2.15 (Unify).** Given two terms $S$ and $T$, the function $\text{unify}(S, T)$ returns an MGU or fails:

```
unify(alpha, alpha) = id                                  -- (1) Same variable
unify(alpha, T)     = if alpha in FV(T) then FAIL         -- (2) Occurs check
                      else [alpha -> T]                    -- (3) Var elimination
unify(S, alpha)     = unify(alpha, S)                     -- (4) Symmetry
unify(f(S1,...,Sn), g(T1,...,Tm)) =
    if f != g or n != m then FAIL                         -- (5) Symbol clash
    else unify_list([(S1,T1),...,(Sn,Tn)], id)            -- (6) Decomposition

unify_list([], sigma)          = sigma
unify_list((S,T)::rest, sigma) =
    let sigma1 = unify(sigma(S), sigma(T))
    in unify_list(rest, sigma1 o sigma)
```

Let us annotate each case in detail:

**(1) Trivial:** A variable unifies with itself via the identity substitution. The equation $\alpha \doteq \alpha$ is trivially satisfied; no binding is needed.

**(2) Occurs check:** If $\alpha$ occurs in $T$ and $\alpha \neq T$, then no finite substitution can make $\alpha$ equal to $T$. The reason is that any substitution $[\alpha \mapsto S]$ would replace $\alpha$ in $T$ by $S$, yielding a term that still contains $S$ in the position where $\alpha$ was---plus the structure around it. The result is always strictly larger than $S$, so $S \neq$ (result). Failure is reported.

**(3) Variable elimination:** If $\alpha \notin \text{FV}(T)$, then $[\alpha \mapsto T]$ is an MGU. The equation becomes $T = T$ after applying this substitution. Moreover, no less committal substitution works: we must bind $\alpha$ to at least $T$.

**(4) Symmetry:** If the left-hand side is a compound term and the right-hand side is a variable, swap and apply case (2) or (3). This ensures we always try variable elimination when possible.

**(5) Symbol clash:** Two terms with different head function symbols cannot be unified. For example, $\text{Int} \doteq \text{Bool}$ or $\to(S_1, S_2) \doteq \text{List}(T_1)$. These are structurally incompatible. Failure is reported.

**(6) Decomposition:** Two terms with the same head symbol $f$ of arity $n$ unify if and only if their corresponding arguments unify pairwise. We solve the argument equations left to right, threading the accumulated substitution through subsequent equations. This threading is essential: solving an earlier equation may constrain variables that appear in later equations.

### 2.4 Worked Examples

**Example 2.16.** Unify $\alpha \to \beta$ and $(\gamma \to \gamma) \to (\delta \to \delta)$.

In our type language, both terms have head symbol $\to$:
- $S = \to(\alpha, \beta)$
- $T = \to(\to(\gamma, \gamma), \to(\delta, \delta))$

Step 1: Decompose. Subproblems: $(\alpha, \gamma \to \gamma)$ and $(\beta, \delta \to \delta)$. Initial $\sigma = \text{id}$.

Step 2: $\text{unify}(\alpha, \gamma \to \gamma)$. No occurs check issue ($\alpha \notin \{\gamma\}$). Result: $\sigma_1 = [\alpha \mapsto \gamma \to \gamma]$.

Step 3: Apply $\sigma_1$ to the remaining pair: $(\sigma_1(\beta), \sigma_1(\delta \to \delta)) = (\beta, \delta \to \delta)$. ($\beta$ and $\delta$ are not affected by $\sigma_1$.)

Step 4: $\text{unify}(\beta, \delta \to \delta)$. No occurs check. Result: $\sigma_2 = [\beta \mapsto \delta \to \delta]$.

Step 5: Compose: $\sigma = \sigma_2 \circ \sigma_1 = [\alpha \mapsto \gamma \to \gamma, \beta \mapsto \delta \to \delta]$.

Verify: $\sigma(\alpha \to \beta) = (\gamma \to \gamma) \to (\delta \to \delta) = \sigma((\gamma \to \gamma) \to (\delta \to \delta))$. Correct.

**Example 2.17.** Unify $\alpha \to \alpha$ and $\beta \to (\beta \to \beta)$.

Step 1: Decompose. Subproblems: $(\alpha, \beta)$ and $(\alpha, \beta \to \beta)$. Initial $\sigma = \text{id}$.

Step 2: $\text{unify}(\alpha, \beta) = [\alpha \mapsto \beta]$. Set $\sigma_1 = [\alpha \mapsto \beta]$.

Step 3: Apply $\sigma_1$ to the remaining pair: $(\sigma_1(\alpha), \sigma_1(\beta \to \beta)) = (\beta, \beta \to \beta)$.

Step 4: $\text{unify}(\beta, \beta \to \beta)$. Occurs check: $\beta \in \text{FV}(\beta \to \beta)$ and $\beta \neq \beta \to \beta$. **FAIL.**

This means $\alpha \to \alpha \doteq \beta \to (\beta \to \beta)$ has no solution. Intuitively, if $\alpha = \beta$, then we need $\beta = \beta \to \beta$, which requires an infinite type.

**Example 2.18.** Unify $(\alpha \to \beta) \to \gamma$ and $\delta \to (\delta \to \varepsilon)$.

Step 1: Decompose: $(\alpha \to \beta, \delta)$ and $(\gamma, \delta \to \varepsilon)$.

Step 2: $\text{unify}(\alpha \to \beta, \delta)$. By case (4), this becomes $\text{unify}(\delta, \alpha \to \beta) = [\delta \mapsto \alpha \to \beta]$. No occurs check issue. Set $\sigma_1 = [\delta \mapsto \alpha \to \beta]$.

Step 3: Apply $\sigma_1$: $(\sigma_1(\gamma), \sigma_1(\delta \to \varepsilon)) = (\gamma, (\alpha \to \beta) \to \varepsilon)$.

Step 4: $\text{unify}(\gamma, (\alpha \to \beta) \to \varepsilon) = [\gamma \mapsto (\alpha \to \beta) \to \varepsilon]$. Set $\sigma_2 = [\gamma \mapsto (\alpha \to \beta) \to \varepsilon]$.

Step 5: $\sigma = \sigma_2 \circ \sigma_1 = [\delta \mapsto \alpha \to \beta, \gamma \mapsto (\alpha \to \beta) \to \varepsilon]$.

Verify: $\sigma((\alpha \to \beta) \to \gamma) = (\alpha \to \beta) \to (\alpha \to \beta) \to \varepsilon$.
$\sigma(\delta \to (\delta \to \varepsilon)) = (\alpha \to \beta) \to ((\alpha \to \beta) \to \varepsilon)$. These are equal. Correct.

**Example 2.19.** Unify two type expressions arising from constraint generation. Consider the constraint set from the "twice" function (Example 2.41 of Lecture 05a):

$$\mathcal{E} = \{\alpha_1 \doteq \alpha_2 \to \alpha_3,\; \alpha_1 \doteq \alpha_3 \to \alpha_4\}$$

Step 1: Solve $\alpha_1 \doteq \alpha_2 \to \alpha_3$. Result: $\sigma_1 = [\alpha_1 \mapsto \alpha_2 \to \alpha_3]$.

Step 2: Apply $\sigma_1$ to the second equation: $\sigma_1(\alpha_1) \doteq \sigma_1(\alpha_3 \to \alpha_4)$, i.e., $\alpha_2 \to \alpha_3 \doteq \alpha_3 \to \alpha_4$.

Step 3: Decompose: $\alpha_2 \doteq \alpha_3$ and $\alpha_3 \doteq \alpha_4$.

Step 4: Solve $\alpha_2 \doteq \alpha_3$: $\sigma_2 = [\alpha_2 \mapsto \alpha_3]$.

Step 5: Apply $\sigma_2$ to $\alpha_3 \doteq \alpha_4$: unchanged (neither variable is in $\text{dom}(\sigma_2)$). Solve: $\sigma_3 = [\alpha_4 \mapsto \alpha_3]$.

Step 6: Compose: $\sigma = \sigma_3 \circ \sigma_2 \circ \sigma_1 = [\alpha_1 \mapsto \alpha_3 \to \alpha_3, \alpha_2 \mapsto \alpha_3, \alpha_4 \mapsto \alpha_3]$.

**Example 2.20.** A system from type inference with an occurs check failure:

$$\mathcal{E} = \{\alpha_1 \doteq \alpha_2 \to \alpha_3,\; \alpha_1 \doteq \alpha_4 \to \alpha_5,\; \alpha_3 \doteq \alpha_5 \to \alpha_6\}$$

Step 1: Solve $\alpha_1 \doteq \alpha_2 \to \alpha_3$: $\sigma_1 = [\alpha_1 \mapsto \alpha_2 \to \alpha_3]$.

Step 2: Apply to second equation: $\alpha_2 \to \alpha_3 \doteq \alpha_4 \to \alpha_5$. Decompose: $\alpha_2 \doteq \alpha_4$, $\alpha_3 \doteq \alpha_5$. Solve: $\sigma_2 = [\alpha_2 \mapsto \alpha_4]$, $\sigma_3 = [\alpha_3 \mapsto \alpha_5]$.

Composed so far: $\sigma_{1..3} = [\alpha_1 \mapsto \alpha_4 \to \alpha_5, \alpha_2 \mapsto \alpha_4, \alpha_3 \mapsto \alpha_5]$.

Step 3: Apply $\sigma_{1..3}$ to third equation: $\alpha_5 \doteq \alpha_5 \to \alpha_6$. Occurs check: $\alpha_5 \in \text{FV}(\alpha_5 \to \alpha_6)$. **FAIL.**

### 2.5 The Occurs Check

The occurs check is the test in case (2) of Robinson's algorithm. It is essential for correctness.

**Theorem 2.21 (Necessity of the Occurs Check).** If $\alpha \in \text{FV}(T)$ and $\alpha \neq T$, then the equation $\alpha \doteq T$ has no unifier.

*Proof.* Suppose for contradiction that $\sigma$ is a unifier, i.e., $\sigma(\alpha) = \sigma(T)$.

Since $\alpha \in \text{FV}(T)$ and $\alpha \neq T$, the term $T$ properly contains $\alpha$ as a subterm. That is, $T = C[\alpha]$ for some non-trivial context $C$ (a term with a "hole" at one or more positions where $\alpha$ occurs).

For any substitution $\sigma$: $\sigma(T) = \sigma(C[\alpha]) = C'[\sigma(\alpha)]$ where $C'$ is the context obtained by applying $\sigma$ to $C$ (but not to the hole). Since $C$ is non-trivial (it is not just a hole), $C'$ is also non-trivial, so:

$$|\sigma(T)| = |C'[\sigma(\alpha)]| > |\sigma(\alpha)|$$

But $\sigma(\alpha) = \sigma(T)$ requires $|\sigma(\alpha)| = |\sigma(T)|$, a contradiction. $\square$

**Alternative proof via well-foundedness.** Define the size of a type expression as above. If $\sigma(\alpha) = \sigma(T)$ and $\alpha$ occurs properly in $T$, then $|\sigma(T)| \geq 1 + |\sigma(\alpha)|$ (the context around $\alpha$ in $T$ contributes at least one node). But $|\sigma(\alpha)| = |\sigma(T)|$, so $|\sigma(\alpha)| \geq 1 + |\sigma(\alpha)|$, which is impossible for natural numbers. $\square$

**Remark 2.22 (Omitting the Occurs Check).** Some implementations---notably early Prolog systems---omit the occurs check for performance reasons. This has several consequences:

1. **Unsoundness:** The system may derive incorrect conclusions. In Prolog, omitting the occurs check can lead to non-termination or unsound answers.

2. **Infinite types:** In the context of type inference, omitting the occurs check amounts to allowing infinite (recursive) types. For example, the equation $\alpha = \alpha \to \text{Int}$ would be "solved" by the infinite type $\alpha = (\cdots \to \text{Int}) \to \text{Int}$.

3. **Deliberate use:** Some languages deliberately allow recursive types. OCaml with the `-rectypes` flag permits types like `type t = t -> int`, which are represented as cyclic structures in memory. In this setting, the occurs check is replaced by a cycle-detection mechanism using union-find on a graph representation.

### 2.6 Correctness of Robinson's Algorithm

We prove three properties: termination, soundness, and completeness (the MGU property).

**Theorem 2.23 (Termination).** Robinson's algorithm terminates on all inputs.

*Proof.* We define a well-founded measure on the state of the algorithm and show it strictly decreases at each step.

For a single call $\text{unify}(S, T)$, define $\mu(S, T) = |S| + |T|$ (the sum of term sizes). We show that the measure decreases in recursive calls:

- Cases (1), (2), (3), (5): The algorithm returns immediately (no recursion).
- Case (4): Swaps arguments and recurses, but the sum $|S| + |T|$ is unchanged. However, after the swap, we fall into case (2) or (3), which returns immediately. So case (4) adds at most one recursive call before termination.
- Case (6): Decomposes $f(S_1, \ldots, S_n) \doteq f(T_1, \ldots, T_n)$ into pairs $(S_1, T_1), \ldots, (S_n, T_n)$. Each pair has $|S_i| + |T_i| < |f(S_1, \ldots, S_n)| + |f(T_1, \ldots, T_n)|$ since $|S_i| < |f(S_1, \ldots, S_n)|$.

For $\text{unify\_list}$, the measure is more subtle because applying the accumulated substitution can increase term sizes. We use a different measure: the number of unsolved variables.

Define the measure for $\text{unify\_list}(\text{pairs}, \sigma)$ as the pair $(V, M)$ in lexicographic order, where:
- $V = |\text{FV}(\text{pairs})|$ is the number of distinct variables in the remaining pairs.
- $M = \sum_{(S, T) \in \text{pairs}} |S| + |T|$ is the total size of remaining terms.

Each call to $\text{unify}$ within $\text{unify\_list}$ either:
- Fails (terminating), or
- Returns a substitution that eliminates at least one variable (case 3), reducing $V$ by at least 1. The substitution may increase $M$, but $V$ decreases, so the lexicographic measure decreases.
- Returns $\text{id}$ (case 1), which removes the current pair without changing anything, reducing $M$.

Since $(V, M) \in \mathbb{N} \times \mathbb{N}$ with the lexicographic order is well-founded, the algorithm terminates. $\square$

**Theorem 2.24 (Soundness).** If $\text{unify}(S, T) = \sigma$, then $\sigma(S) = \sigma(T)$.

*Proof.* By induction on the recursion structure.

**Case (1):** $S = T = \alpha$. $\text{id}(\alpha) = \alpha = \text{id}(\alpha)$. Sound.

**Case (3):** $S = \alpha$, $\alpha \notin \text{FV}(T)$, $\sigma = [\alpha \mapsto T]$. Then:

$$\sigma(\alpha) = T$$

$$\sigma(T) = T \quad \text{(since } \alpha \notin \text{FV}(T)\text{, the substitution does not affect } T\text{)}$$

So $\sigma(\alpha) = \sigma(T) = T$. Sound.

**Case (4):** $\text{unify}(S, \alpha) = \text{unify}(\alpha, S)$. By the induction hypothesis applied to $\text{unify}(\alpha, S) = \sigma$, we get $\sigma(\alpha) = \sigma(S)$, which implies $\sigma(S) = \sigma(\alpha)$. Sound.

**Case (6):** $S = f(S_1, \ldots, S_n)$, $T = f(T_1, \ldots, T_n)$. The algorithm calls $\text{unify\_list}$ on the pairs $(S_i, T_i)$, producing $\sigma$.

We prove soundness of $\text{unify\_list}$ by induction on the length of the list:

Base case: empty list, $\sigma = \sigma_{\text{acc}}$ (the accumulated substitution). No equations to satisfy. Sound.

Inductive case: list is $(S, T) :: \text{rest}$, accumulated substitution is $\sigma_{\text{acc}}$. The algorithm computes:

$$\sigma_1 = \text{unify}(\sigma_{\text{acc}}(S), \sigma_{\text{acc}}(T))$$

$$\sigma' = \text{unify\_list}(\text{rest}, \sigma_1 \circ \sigma_{\text{acc}})$$

By the induction hypothesis on $\text{unify}$: $\sigma_1(\sigma_{\text{acc}}(S)) = \sigma_1(\sigma_{\text{acc}}(T))$.

By the induction hypothesis on $\text{unify\_list}$: for each $(S_j, T_j) \in \text{rest}$, $\sigma'(S_j) = \sigma'(T_j)$.

Since $\sigma' = \sigma_k \circ \cdots \circ \sigma_1 \circ \sigma_{\text{acc}}$ (composing all intermediate substitutions), and $\sigma_1(\sigma_{\text{acc}}(S)) = \sigma_1(\sigma_{\text{acc}}(T))$, applying $\sigma_k \circ \cdots \circ \sigma_2$ to both sides preserves equality: $\sigma'(S) = \sigma'(T)$.

Therefore $\sigma'(f(S_1, \ldots, S_n)) = f(\sigma'(S_1), \ldots, \sigma'(S_n)) = f(\sigma'(T_1), \ldots, \sigma'(T_n)) = \sigma'(f(T_1, \ldots, T_n))$. $\square$

**Theorem 2.25 (Completeness / MGU Property).** If $\text{unify}(S, T) = \sigma$, then $\sigma$ is a most general unifier: for every unifier $\sigma'$ of $S \doteq T$, there exists $\delta$ such that $\sigma' = \delta \circ \sigma$.

*Proof.* By induction on the recursion structure.

**Case (1):** $S = T = \alpha$. $\sigma = \text{id}$. For any unifier $\sigma'$: $\sigma' = \sigma' \circ \text{id} = \sigma' \circ \sigma$. Take $\delta = \sigma'$.

**Case (3):** $S = \alpha$, $\alpha \notin \text{FV}(T)$, $\sigma = [\alpha \mapsto T]$. Let $\sigma'$ be any unifier: $\sigma'(\alpha) = \sigma'(T)$.

Define $\delta$ as follows: for any variable $\beta$, set $\delta(\beta) = \sigma'(\beta)$. Then for $\beta \neq \alpha$:

$$(\delta \circ \sigma)(\beta) = \delta(\sigma(\beta)) = \delta(\beta) = \sigma'(\beta)$$

since $\sigma(\beta) = \beta$ for $\beta \neq \alpha$ (and $\beta \notin \text{dom}(\sigma)$ when $\beta \neq \alpha$).

For $\alpha$:

$$(\delta \circ \sigma)(\alpha) = \delta(\sigma(\alpha)) = \delta(T) = \sigma'(T) = \sigma'(\alpha)$$

The equality $\delta(T) = \sigma'(T)$ holds because for every variable $\beta$ in $T$ (and $\alpha \notin \text{FV}(T)$), we have $\delta(\beta) = \sigma'(\beta)$, so $\delta$ and $\sigma'$ agree on all variables of $T$.

Therefore $\sigma' = \delta \circ \sigma$.

**Case (6):** The proof extends by induction on the list. Let $\sigma = \sigma_n \circ \cdots \circ \sigma_1$ be the composition of MGUs for each sub-equation. Let $\sigma'$ be any unifier of the whole system.

Since $\sigma'$ unifies the first equation, and $\sigma_1$ is its MGU, there exists $\delta_1$ with $\sigma' = \delta_1 \circ \sigma_1$. Now $\delta_1$ must unify the remaining equations (after applying $\sigma_1$). Since $\sigma_2$ is the MGU of the second equation (after $\sigma_1$), there exists $\delta_2$ with $\delta_1 = \delta_2 \circ \sigma_2$. Continuing:

$$\sigma' = \delta_1 \circ \sigma_1 = \delta_2 \circ \sigma_2 \circ \sigma_1 = \cdots = \delta_n \circ \sigma_n \circ \cdots \circ \sigma_1 = \delta_n \circ \sigma$$

Take $\delta = \delta_n$. $\square$

### 2.7 Uniqueness of the MGU

**Theorem 2.26 (Uniqueness up to Renaming).** If $\sigma$ and $\sigma'$ are both MGUs of $\mathcal{E}$, then there exists a variable renaming $\rho$ (a bijection on variables, extended to terms) such that $\sigma' = \rho \circ \sigma$ restricted to $\text{FV}(\mathcal{E})$.

*Proof.* Since $\sigma$ is an MGU and $\sigma'$ is a unifier, there exists $\delta$ with $\sigma' = \delta \circ \sigma$. Since $\sigma'$ is an MGU and $\sigma$ is a unifier, there exists $\delta'$ with $\sigma = \delta' \circ \sigma'$. Substituting:

$$\sigma = \delta' \circ \sigma' = \delta' \circ \delta \circ \sigma$$

This means $(\delta' \circ \delta)$ is the identity on all terms in the range of $\sigma$ (restricted to the variables of $\mathcal{E}$). Similarly, $\sigma' = \delta \circ \delta' \circ \sigma'$ implies $(\delta \circ \delta')$ is the identity on all terms in the range of $\sigma'$.

For variables $\alpha$ in $\text{ran}(\sigma)$: $\delta'(\delta(\alpha)) = \alpha$, so $\delta'$ is a left inverse of $\delta$ on these variables. Similarly, $\delta(\delta'(\beta)) = \beta$ for $\beta \in \text{ran}(\sigma')$. Therefore $\delta$ restricted to the relevant variables is a bijection (a renaming), and $\sigma' = \delta \circ \sigma$ where $\delta$ is a renaming. $\square$

### 2.8 Properties of the MGU

**Lemma 2.27 (Idempotence).** The MGU produced by Robinson's algorithm is idempotent.

*Proof.* We show $\text{dom}(\sigma) \cap \text{ran}(\sigma) = \emptyset$ by induction on the algorithm.

In case (3), $\sigma = [\alpha \mapsto T]$ with $\alpha \notin \text{FV}(T)$. So $\text{dom}(\sigma) = \{\alpha\}$ and $\text{ran}(\sigma) = \text{FV}(T)$. Since $\alpha \notin \text{FV}(T)$, the intersection is empty.

In case (6), the composition $\sigma_n \circ \cdots \circ \sigma_1$ requires induction. After applying $\sigma_1 = [\alpha_1 \mapsto T_1]$, the variable $\alpha_1$ is eliminated from all subsequent equations. Subsequent substitutions $\sigma_i$ only bind variables that appear in the (substituted) remaining equations, which do not include $\alpha_1$. By induction, the composed substitution has disjoint domain and range.

By Lemma 2.7, this implies idempotence. $\square$

**Lemma 2.28 (Domain of the MGU).** The MGU $\sigma$ of $\mathcal{E}$ satisfies $\text{dom}(\sigma) \subseteq \text{FV}(\mathcal{E})$.

*Proof.* The algorithm only maps variables that appear in the equations being solved. Case (3) maps $\alpha$, which appears in the current equation. Since all equations derive from $\mathcal{E}$ (possibly with substitutions applied that do not introduce new domain variables), every mapped variable is in $\text{FV}(\mathcal{E})$. $\square$

**Lemma 2.29 (Range of the MGU).** The MGU $\sigma$ of $\mathcal{E}$ satisfies $\text{ran}(\sigma) \subseteq \text{FV}(\mathcal{E})$.

*Proof.* Each binding $[\alpha \mapsto T]$ introduced by the algorithm has $T$ being a subterm of one of the (substituted) equations. All variables in these subterms come from the original equations $\mathcal{E}$ (substitution only renames, it does not introduce variables not already present). $\square$

### 2.9 Complexity Analysis

**Theorem 2.30 (Exponential Worst Case for Naive Robinson).** The naive Robinson algorithm (as presented above, using explicit substitution application) has exponential time and space complexity in the worst case.

*Proof.* Consider the equation system with $n$ equations:

$$\alpha_1 \doteq \alpha_2 \to \alpha_2, \quad \alpha_2 \doteq \alpha_3 \to \alpha_3, \quad \ldots, \quad \alpha_{n-1} \doteq \alpha_n \to \alpha_n$$

After eliminating $\alpha_1$, the substitution is $[\alpha_1 \mapsto \alpha_2 \to \alpha_2]$, and the explicit form of $\sigma(\alpha_1)$ has size 3.

After eliminating $\alpha_2$, we substitute $\alpha_2 \mapsto \alpha_3 \to \alpha_3$ into $\sigma(\alpha_1)$:

$$\sigma(\alpha_1) = (\alpha_3 \to \alpha_3) \to (\alpha_3 \to \alpha_3)$$

Size: 7 = $2 \cdot 3 + 1$.

After $k$ eliminations, $|\sigma(\alpha_1)| = 2^{k+1} - 1$.

After all $n-1$ eliminations, $|\sigma(\alpha_1)| = 2^n - 1$.

The total size of the explicit substitution is $\Theta(2^n)$, so the algorithm takes at least exponential time just to write down the result. $\square$

**Remark 2.31.** The exponential blowup is in the explicit representation. If we represent the substitution as a DAG (directed acyclic graph) with sharing, the size is $O(n)$: each equation adds one node. This observation motivates the efficient implementations.

**Theorem 2.32 (Nearly Linear Unification).** Using a union-find data structure with path compression and union by rank, unification can be performed in $O(n \cdot \alpha(n))$ time, where $n$ is the total size of the input terms and $\alpha$ is the inverse Ackermann function.

This result is due to Paterson and Wegman (1978) and Martelli and Montanari (1982).

*Proof sketch.* The key idea is to avoid explicit substitution application:

1. Represent each type expression as a node in a DAG.
2. Variables and compound terms are nodes; compound terms have edges to their children.
3. When we unify $\alpha$ with $T$ (variable elimination), make $\alpha$'s equivalence class representative point to $T$'s representative (union operation).
4. When we access a variable's current binding, follow the representative pointers (find operation with path compression).
5. When we unify two compound terms $f(S_1, \ldots, S_n) \doteq f(T_1, \ldots, T_n)$, merge their root nodes and recursively unify corresponding children.

Each union and find operation takes amortized $O(\alpha(n))$ time. The total number of operations is proportional to the input size $n$. Therefore the total time is $O(n \cdot \alpha(n))$.

The occurs check requires a DFS through the term structure starting from the node being bound, which takes $O(n)$ in the worst case. However, with careful implementation (checking only the equivalence class representatives), this can be amortized across all operations. $\square$

### 2.10 The Martelli--Montanari Formulation

Martelli and Montanari (1982) presented unification as a set of non-deterministic transformation rules on equation sets. This formulation is elegant and makes the correctness argument transparent.

**Definition 2.33 (Martelli--Montanari Rules).** Starting from a set of equations $\mathcal{E}$ and an empty solved set $\mathcal{S}$, apply the following rules until no rule applies or failure is detected:

**Delete:** $\{t \doteq t\} \cup \mathcal{E}; \mathcal{S} \implies \mathcal{E}; \mathcal{S}$

Remove trivially true equations.

**Decompose:** $\{f(s_1,\ldots,s_n) \doteq f(t_1,\ldots,t_n)\} \cup \mathcal{E}; \mathcal{S} \implies \{s_1 \doteq t_1, \ldots, s_n \doteq t_n\} \cup \mathcal{E}; \mathcal{S}$

Replace an equation between compound terms with equations between their arguments.

**Clash:** $\{f(s_1,\ldots,s_n) \doteq g(t_1,\ldots,t_m)\} \cup \mathcal{E}; \mathcal{S} \implies \bot$ when $f \neq g$ or $n \neq m$

Incompatible head symbols mean no unifier exists.

**Orient:** $\{t \doteq \alpha\} \cup \mathcal{E}; \mathcal{S} \implies \{\alpha \doteq t\} \cup \mathcal{E}; \mathcal{S}$ when $t$ is not a variable

Move variables to the left side for uniform processing.

**Eliminate:** $\{\alpha \doteq t\} \cup \mathcal{E}; \mathcal{S} \implies [\alpha \mapsto t](\mathcal{E}); \mathcal{S} \cup \{\alpha \doteq t\}$ when $\alpha \notin \text{FV}(t)$ and $\alpha \in \text{FV}(\mathcal{E}) \cup \text{FV}(\mathcal{S})$

Substitute the binding for $\alpha$ into all remaining equations and move it to the solved set.

**Check:** $\{\alpha \doteq t\} \cup \mathcal{E}; \mathcal{S} \implies \bot$ when $\alpha \in \text{FV}(t)$ and $\alpha \neq t$

Occurs check failure.

**Theorem 2.34 (Correctness of Martelli--Montanari).** The rules are:

1. **Sound:** each rule preserves the set of unifiers. That is, $\text{Unif}(\mathcal{E} \cup \mathcal{S}) = \text{Unif}(\mathcal{E}' \cup \mathcal{S}')$ for each non-failing transformation.

2. **Terminating:** no infinite sequence of rule applications exists.

3. **Complete:** the normal form (when no rule applies and $\bot$ has not been reached) is a solved set $\mathcal{S}$ of the form $\{\alpha_1 \doteq t_1, \ldots, \alpha_k \doteq t_k\}$ where:
   - The $\alpha_i$ are distinct.
   - $\alpha_i \notin \text{FV}(t_j)$ for all $i, j$.
   - The solved set directly yields the MGU: $\sigma = [\alpha_1 \mapsto t_1, \ldots, \alpha_k \mapsto t_k]$.

*Proof sketch of termination.* Define the measure $\mu(\mathcal{E}, \mathcal{S}) = (V, N, S)$ in lexicographic order, where:
- $V$ = number of variables in $\mathcal{E}$ that do not appear in $\mathcal{S}$ (unsolved variables).
- $N$ = number of equations in $\mathcal{E}$.
- $S$ = total size of all terms in $\mathcal{E}$.

Each rule strictly decreases this measure:
- **Delete:** decreases $N$.
- **Decompose:** increases $N$ but decreases $S$ (replacing one equation with smaller ones).
- **Orient:** does not change the measure but prepares for Eliminate.
- **Eliminate:** decreases $V$ (the eliminated variable moves from $\mathcal{E}$ to $\mathcal{S}$).
- **Clash, Check:** terminate immediately. $\square$

### 2.11 Unification with Type Constructors

In practice, type expressions include not just arrow types but also type constructors: $\text{List}(T)$, $\text{Pair}(T_1, T_2)$, $\text{Option}(T)$, etc.

The unification algorithm extends naturally: each type constructor $C$ of arity $n$ is treated as a function symbol of arity $n$. The decomposition rule becomes:

$$\text{unify}(C(S_1, \ldots, S_n), C(T_1, \ldots, T_n)) = \text{unify\_list}([(S_1,T_1), \ldots, (S_n,T_n)], \text{id})$$

The clash rule applies when constructors differ:

$$\text{unify}(C_1(\ldots), C_2(\ldots)) = \text{FAIL} \quad \text{when } C_1 \neq C_2 \text{ or arities differ}$$

**Example 2.35.** Unify $\text{List}(\alpha \to \beta)$ and $\text{List}(\text{Int} \to \text{Bool})$.

Step 1: Heads match ($\text{List}$). Decompose: $\alpha \to \beta \doteq \text{Int} \to \text{Bool}$.

Step 2: Heads match ($\to$). Decompose: $\alpha \doteq \text{Int}$ and $\beta \doteq \text{Bool}$.

Step 3: $\sigma = [\alpha \mapsto \text{Int}, \beta \mapsto \text{Bool}]$.

**Example 2.36.** Unify $\text{List}(\alpha)$ and $\alpha$.

Occurs check: $\alpha \in \text{FV}(\text{List}(\alpha))$ and $\alpha \neq \text{List}(\alpha)$. FAIL. A list cannot have elements of its own type (without recursive types).

**Example 2.37.** Unify $\text{Pair}(\alpha, \text{Bool})$ and $\text{Pair}(\text{Int}, \beta)$.

Decompose: $\alpha \doteq \text{Int}$ and $\text{Bool} \doteq \beta$. Result: $\sigma = [\alpha \mapsto \text{Int}, \beta \mapsto \text{Bool}]$.

**Example 2.38.** Unify $\text{List}(\alpha)$ and $\text{Pair}(\beta, \gamma)$.

Clash: $\text{List} \neq \text{Pair}$. FAIL.

### 2.12 Unification Modulo Theories

Standard syntactic unification can be extended to unification modulo equational theories. While not needed for basic type inference, these extensions arise in more advanced settings.

**Definition 2.39 (E-unification).** Given an equational theory $E$ (a set of universally quantified equations), E-unification asks: given $S$ and $T$, find $\sigma$ such that $\sigma(S) =_E \sigma(T)$, where $=_E$ is the equivalence relation generated by $E$.

Important cases:

- **AC-unification** (associative-commutative): For an operator $\oplus$ satisfying $a \oplus (b \oplus c) = (a \oplus b) \oplus c$ and $a \oplus b = b \oplus a$. Decidable but NP-complete. Finitely many MGUs may exist (not a single MGU).

- **Unification modulo alpha-equivalence:** Terms are lambda terms, and equality is up to renaming of bound variables. Decidable for first-order terms, but higher-order unification (where variables can range over functions) is undecidable in general.

For ML-style type inference, syntactic unification suffices. E-unification becomes relevant for type-level computation (type families in Haskell, type-level rewriting).

### 2.13 Higher-Order Unification

**Definition 2.40.** Higher-order unification is the problem of unifying terms in the simply typed lambda calculus modulo $\beta\eta$-equality, where variables may range over functions of any type.

**Theorem 2.41 (Huet 1973).** Higher-order unification is undecidable in general.

*Proof sketch.* Huet reduced Hilbert's tenth problem (solvability of Diophantine equations, shown undecidable by Matiyasevich 1970) to higher-order unification. The key idea is to encode natural number arithmetic in the simply typed lambda calculus using Church numerals, then express Diophantine equations as higher-order unification problems. $\square$

Despite undecidability, Huet provided a semi-decision procedure---a complete enumeration of all unifiers that terminates when a unifier exists but may loop when none does. This procedure is used in practice in proof assistants like Coq, Isabelle, and Lean.

**Theorem 2.42 (Miller 1991).** Higher-order pattern unification---where "flex-flex" pairs are restricted to the **pattern fragment** (bound variables are applied only to sequences of distinct bound variables)---is decidable and has most general unifiers. This fragment covers the vast majority of unification problems arising in practice in dependently typed languages.

### 2.14 Unification in the Context of Type Inference

Returning to the type inference setting, we now have all the tools to state the main result precisely.

**Theorem 2.43 (Principal Type via Unification).** Let $t$ be a raw term and $\Gamma$ a context. Let $\mathcal{CG}(\Gamma, t) = (T, C)$ be the result of constraint generation (Lecture 05a). Let $\sigma = \text{mgu}(C)$ if it exists. Then:

1. $\sigma(\Gamma) \vdash t : \sigma(T)$ (the result is a valid typing).
2. $\sigma(T)$ is the principal type of $t$ under $\Gamma$ (every other valid type is an instance).

*Proof.* Part (1): By soundness of constraint generation (Theorem 2.43 of Lecture 05a), since $\sigma \models C$, we have $\sigma(\Gamma) \vdash t : \sigma(T)$.

Part (2): Let $(\tau, T')$ be any solution to the type reconstruction problem, i.e., $\tau(\Gamma) \vdash t : T'$. By completeness of constraint generation (Theorem 2.44 of Lecture 05a), there exists a unifier $\rho$ of $C$ with $\rho(T) = T'$. By the MGU property (Theorem 2.25), there exists $\delta$ with $\rho = \delta \circ \sigma$. Therefore:

$$T' = \rho(T) = \delta(\sigma(T))$$

showing that $T'$ is an instance of $\sigma(T)$. Since this holds for every solution, $\sigma(T)$ is the principal type. $\square$

### 2.15 Triangular vs. Idempotent Substitutions

There are two common representations for substitutions in implementations.

**Definition 2.44 (Idempotent Substitution).** An idempotent substitution $\sigma$ satisfies $\sigma \circ \sigma = \sigma$. Equivalently, $\text{dom}(\sigma) \cap \text{ran}(\sigma) = \emptyset$ (Lemma 2.7). All bindings are "fully resolved": the range contains no variables that are themselves in the domain.

**Definition 2.45 (Triangular Substitution).** A triangular substitution is a sequence of bindings $[\alpha_1 \mapsto T_1, \alpha_2 \mapsto T_2, \ldots, \alpha_n \mapsto T_n]$ where the binding for $\alpha_i$ may contain variables $\alpha_j$ with $j > i$. To look up the value of $\alpha_i$, we apply the subsequent bindings $[\alpha_{i+1} \mapsto T_{i+1}, \ldots, \alpha_n \mapsto T_n]$ to $T_i$.

**Example 2.46.** The idempotent substitution $[\alpha \mapsto \text{Int} \to \text{Int}, \beta \mapsto \text{Int}]$ can also be represented as the triangular substitution $[\alpha \mapsto \beta \to \beta, \beta \mapsto \text{Int}]$. To look up $\alpha$: first get $\beta \to \beta$, then apply $[\beta \mapsto \text{Int}]$ to get $\text{Int} \to \text{Int}$.

**Advantages of triangular substitutions:**
- Cheaper to construct: composition does not require applying one substitution to all bindings of another.
- The substitution produced by Robinson's algorithm is naturally triangular: each step adds one binding at the end.
- Space-efficient: the triangular form avoids duplicating terms that result from substitution application.

**Disadvantages:**
- Lookup requires traversing the chain of bindings, which can take $O(n)$ per lookup in the worst case.
- With path compression (as in union-find), this can be amortized to nearly $O(1)$.

In practice, efficient implementations use a union-find data structure, which is essentially a graph-based representation of a triangular substitution with path compression.

### 2.16 Unification and Lattice Theory

The set of substitutions, ordered by the "more general" relation $\leq$, has interesting lattice-theoretic properties.

**Definition 2.47 (Pre-lattice of Substitutions).** The preorder $(\text{Subst}, \leq)$ where $\sigma_1 \leq \sigma_2$ iff $\sigma_2 = \delta \circ \sigma_1$ for some $\delta$ is a pre-lattice:

- The identity substitution $\text{id}$ is the bottom element: $\text{id} \leq \sigma$ for all $\sigma$ (take $\delta = \sigma$).
- The MGU of two terms $S$ and $T$ is the greatest lower bound (meet) of the set of all unifiers of $S \doteq T$ in this preorder.

**Theorem 2.48.** For any unification problem $\mathcal{E}$: either $\text{Unif}(\mathcal{E}) = \emptyset$ (no unifiers exist), or $\text{Unif}(\mathcal{E})$ has a unique minimum element in the preorder $(\text{Subst}/{\sim}, \leq)$, which is the equivalence class of the MGU.

*Proof.* The MGU $\sigma$ satisfies $\sigma \leq \sigma'$ for all $\sigma' \in \text{Unif}(\mathcal{E})$ by definition. Uniqueness (up to $\sim$, i.e., up to variable renaming) was shown in Theorem 2.26. $\square$

**Remark 2.49.** This property---that the set of unifiers has a unique minimum element---is specific to first-order syntactic unification. For unification modulo equational theories (e.g., AC-unification), the set of minimal unifiers may be finite but not a singleton: there may be multiple incomparable most general unifiers.

### 2.17 The Unification Closure

**Definition 2.50 (Unification Closure).** Given a constraint set $C$, the unification closure $\text{cl}(C)$ is the smallest set of equations closed under the following rules:

1. $C \subseteq \text{cl}(C)$ (all original equations are included).
2. If $(S \doteq T) \in \text{cl}(C)$, then $(T \doteq S) \in \text{cl}(C)$ (symmetry).
3. If $(S \doteq T) \in \text{cl}(C)$ and $(T \doteq U) \in \text{cl}(C)$, then $(S \doteq U) \in \text{cl}(C)$ (transitivity).
4. If $(f(S_1, \ldots, S_n) \doteq f(T_1, \ldots, T_n)) \in \text{cl}(C)$, then $(S_i \doteq T_i) \in \text{cl}(C)$ for all $i$ (decomposition).

**Lemma 2.51.** The constraint set $C$ is satisfiable if and only if $\text{cl}(C)$ contains no equation $f(\ldots) \doteq g(\ldots)$ with $f \neq g$ and no equation $\alpha \doteq T$ where $\alpha \in \text{FV}(T)$ and $\alpha \neq T$.

This gives a declarative characterization of satisfiability, complementing the algorithmic characterization provided by Robinson's algorithm.

### 2.18 Correctness via the Knuth--Bendix Analogy

The Martelli--Montanari rules can be viewed as a special case of the Knuth--Bendix completion procedure for equational reasoning. In this analogy:

- Equations $S \doteq T$ correspond to rewrite rules $S \to T$ (oriented by the variable elimination rule).
- The solved form corresponds to a convergent (confluent and terminating) rewrite system.
- The MGU corresponds to the normal form of a term under the completed system.

This connection is more than an analogy: it provides a principled way to extend unification to equational theories. Given a set of equations $E$, E-unification can sometimes be solved by first completing $E$ into a convergent system using Knuth--Bendix completion, then using the completed system for normalization-based unification.

### 2.19 Unification for Constraint Solving in Type Inference

Let us work through a complete type inference example end-to-end, showing how unification solves the constraints generated by the algorithm of Lecture 05a.

**Example 2.52 (Complete inference of the S combinator).** Consider the term:

$$S = \lambda x.\; \lambda y.\; \lambda z.\; x\;z\;(y\;z)$$

**Constraint generation:** Under $\Gamma = \emptyset$:

- Introduce $\alpha_1$ for $x$, $\alpha_2$ for $y$, $\alpha_3$ for $z$.
- For $x\;z$: introduce $\alpha_4$, constraint $C_1: \alpha_1 = \alpha_3 \to \alpha_4$.
- For $y\;z$: introduce $\alpha_5$, constraint $C_2: \alpha_2 = \alpha_3 \to \alpha_5$.
- For $(x\;z)\;(y\;z)$: introduce $\alpha_6$, constraint $C_3: \alpha_4 = \alpha_5 \to \alpha_6$.

Result type: $\alpha_1 \to \alpha_2 \to \alpha_3 \to \alpha_6$.

Constraints: $\{C_1, C_2, C_3\}$.

**Unification (solving the constraints):**

Step 1: Solve $C_1$: $\alpha_1 = \alpha_3 \to \alpha_4$. Variable $\alpha_1$ does not occur in $\alpha_3 \to \alpha_4$. MGU: $\sigma_1 = [\alpha_1 \mapsto \alpha_3 \to \alpha_4]$.

Step 2: Apply $\sigma_1$ to $C_2$: $\sigma_1(\alpha_2) = \sigma_1(\alpha_3 \to \alpha_5)$, i.e., $\alpha_2 = \alpha_3 \to \alpha_5$ (neither $\alpha_2$, $\alpha_3$, nor $\alpha_5$ are in $\text{dom}(\sigma_1)$). Solve: $\sigma_2 = [\alpha_2 \mapsto \alpha_3 \to \alpha_5]$.

Step 3: Apply $\sigma_2 \circ \sigma_1$ to $C_3$: $(\sigma_2 \circ \sigma_1)(\alpha_4) = (\sigma_2 \circ \sigma_1)(\alpha_5 \to \alpha_6)$, i.e., $\alpha_4 = \alpha_5 \to \alpha_6$. Solve: $\sigma_3 = [\alpha_4 \mapsto \alpha_5 \to \alpha_6]$.

Combined substitution: $\sigma = \sigma_3 \circ \sigma_2 \circ \sigma_1 = [\alpha_1 \mapsto \alpha_3 \to (\alpha_5 \to \alpha_6), \alpha_2 \mapsto \alpha_3 \to \alpha_5, \alpha_4 \mapsto \alpha_5 \to \alpha_6]$.

Apply to result type:

$$\sigma(\alpha_1 \to \alpha_2 \to \alpha_3 \to \alpha_6) = (\alpha_3 \to \alpha_5 \to \alpha_6) \to (\alpha_3 \to \alpha_5) \to \alpha_3 \to \alpha_6$$

Renaming $\alpha_3 \to A$, $\alpha_5 \to B$, $\alpha_6 \to C$:

$$(A \to B \to C) \to (A \to B) \to A \to C$$

This is the standard type of the S combinator, corresponding to the axiom scheme $S$ of combinatory logic and to the formula $(A \Rightarrow B \Rightarrow C) \Rightarrow (A \Rightarrow B) \Rightarrow A \Rightarrow C$ in intuitionistic propositional logic.

**Example 2.53 (Complete inference of a nested application).** Consider:

$$t = \lambda f.\; \lambda x.\; f\;(f\;(f\;x))$$

Constraint generation:

- Introduce $\alpha_1$ for $f$, $\alpha_2$ for $x$.
- For $f\;x$: introduce $\alpha_3$, constraint $\alpha_1 = \alpha_2 \to \alpha_3$.
- For $f\;(f\;x)$: introduce $\alpha_4$, constraint $\alpha_1 = \alpha_3 \to \alpha_4$.
- For $f\;(f\;(f\;x))$: introduce $\alpha_5$, constraint $\alpha_1 = \alpha_4 \to \alpha_5$.

Constraints: $\{\alpha_1 = \alpha_2 \to \alpha_3, \alpha_1 = \alpha_3 \to \alpha_4, \alpha_1 = \alpha_4 \to \alpha_5\}$.

Solving step by step:

From $\alpha_1 = \alpha_2 \to \alpha_3$ and $\alpha_1 = \alpha_3 \to \alpha_4$:
$\alpha_2 \to \alpha_3 = \alpha_3 \to \alpha_4$, so $\alpha_2 = \alpha_3$ and $\alpha_3 = \alpha_4$.

From $\alpha_1 = \alpha_4 \to \alpha_5$ and $\alpha_1 = \alpha_2 \to \alpha_3$ (with $\alpha_2 = \alpha_3 = \alpha_4$):
$\alpha_4 \to \alpha_5 = \alpha_4 \to \alpha_4$ (since $\alpha_2 = \alpha_3 = \alpha_4$), so $\alpha_5 = \alpha_4$.

All type variables equal: $\alpha_2 = \alpha_3 = \alpha_4 = \alpha_5$.

Principal type: $(\alpha \to \alpha) \to \alpha \to \alpha$.

This matches our intuition: applying $f$ three times requires $f$ to be an endofunction.

### 2.20 Error Reporting

When unification fails, the nature of the failure provides valuable diagnostic information.

**Clash failure.** The terms have incompatible head constructors. This typically means the programmer used a value of the wrong type. Example error message: "Expected type $S \to T$ but found type $\text{Int}$."

**Occurs check failure.** A type would need to be infinite. This typically means the programmer wrote a self-referential expression. Example error message: "Cannot construct the infinite type $\alpha \sim \alpha \to \beta$."

**Provenance tracking.** Modern type inference engines record which source location generated each constraint. When unification fails, this provenance information is used to report the error at the most relevant location, rather than at the point where unification happens to fail.

**Techniques for better error messages:**

1. **Tracking provenance:** each constraint is annotated with the source location that generated it. When unification fails, the system reports both the failing constraint and its source.

2. **Bidirectional error flow:** rather than always reporting the error at the unification call site, the system analyzes the constraint graph to find the "most informative" location.

3. **Type error slicing (Haack and Wells 2004):** identify the minimal subset of the program that is responsible for the type error. This subset may span multiple source locations.

4. **Type error debugging (Chitil 2001):** present the type error as a series of steps that led to the contradiction, allowing the programmer to identify which step introduced the mistake.

### 2.21 Correctness via Invariant Preservation

An alternative proof strategy for the correctness of Robinson's algorithm uses an invariant-based approach, which is sometimes easier to follow than the inductive proof.

**Definition 2.54 (Invariant).** At each step of the algorithm, the following invariant holds:

$$\text{Unif}(\sigma_{\text{acc}} \cup \text{remaining equations}) = \text{Unif}(\text{original equations})$$

where $\sigma_{\text{acc}}$ is the accumulated substitution (viewed as a set of equations $\{\alpha_i \doteq T_i\}$) and "remaining equations" are the equations not yet processed.

**Theorem 2.55.** Robinson's algorithm preserves this invariant.

*Proof sketch.* Each case of the algorithm transforms the set of equations while preserving the set of unifiers:

- **Delete** ($t \doteq t$): the equation is trivially satisfied by all substitutions, so removing it does not change the set of unifiers.

- **Decompose** ($f(S_1, \ldots, S_n) \doteq f(T_1, \ldots, T_n) \implies S_i \doteq T_i$): a substitution unifies the compound terms iff it unifies all corresponding arguments.

- **Eliminate** ($\alpha \doteq T \implies$ substitute $\alpha$ everywhere): a substitution satisfies the original equations iff it satisfies the equations with $\alpha$ replaced by $T$ plus the binding $\alpha \mapsto T$.

- **Clash and Check**: the equation set has no unifiers, so both sides of the invariant are $\emptyset$.

When the algorithm terminates with a solved form, the invariant gives us $\text{Unif}(\sigma) = \text{Unif}(\text{original})$. Since $\sigma$ is clearly a unifier of itself (the identity satisfies it), $\sigma$ is a unifier of the original. Moreover, any unifier of the original is a unifier of $\sigma$, which means it factors through $\sigma$, establishing the MGU property. $\square$

### 2.22 Unification and Type Error Messages in Practice

Let us examine how modern compilers use unification failure information to produce helpful error messages.

**Example 2.56 (OCaml-style error).** Consider the OCaml expression:

```ocaml
let f x = x + 1 in f "hello"
```

The constraint generation produces:
- From `x + 1`: $\alpha_x = \text{int}$ (since `+` has type `int -> int -> int`).
- From `f "hello"`: $\alpha_x = \text{string}$ (since `"hello"` has type `string`).

Unification of `int` and `string` fails (clash). OCaml reports:

```
Error: This expression has type string but an expression of type int was expected
```

The constraint-based approach allows the compiler to trace back from the failed unification to the source locations that generated the conflicting constraints, producing a more informative message than just "unification failed."

**Example 2.57 (Occurs check error).** Consider:

```ocaml
let rec f x = f
```

Here, `f : 'a -> 'b` and the body `f` has the same type. But `f` is also the return value, so `'b = 'a -> 'b`. This fails the occurs check. OCaml reports:

```
Error: This expression has type 'a -> 'b
       but an expression of type 'b was expected.
       The type variable 'b occurs inside 'a -> 'b
```

### 2.23 Unification with Rigid and Flexible Variables

In some settings (particularly with GADTs and dependent types), not all type variables are equally "free." Some variables are rigid (cannot be instantiated) and others are flexible (can be instantiated by the unifier).

**Definition 2.58 (Rigid Variable).** A rigid variable $\alpha$ is one that must not be instantiated by the unifier. An equation $\alpha \doteq T$ where $\alpha$ is rigid is satisfiable only if $T = \alpha$.

**Definition 2.59 (Flexible Variable).** A flexible variable is one that the unifier may instantiate freely, as in standard unification.

This distinction arises naturally in GADT pattern matching, where the type variables introduced by the constructor's type signature are locally known but must not "leak" to the enclosing scope.

**Example 2.60.** In the GADT branch:

```
| IntLit n -> n    (* here, the return type is refined to int *)
```

The type variable `a` from the scrutinee type `a expr` is rigid within this branch (it is known to be `int`), but flexible in the overall function type.

### 2.24 Unification and the Word Problem

Unification is closely related to the word problem in algebra.

**Definition 2.61 (Word Problem).** Given an equational theory $E$ and two terms $s, t$, the word problem asks: is $s =_E t$? That is, can $s$ be transformed into $t$ by applying the equations in $E$ as rewrite rules?

**Theorem 2.62.** The word problem is decidable for free algebras (no equations), undecidable for general equational theories, and decidable for specific theories (e.g., groups, commutative rings).

Syntactic unification corresponds to the word problem in a free algebra: given $s$ and $t$ with variables, find a substitution $\sigma$ such that $\sigma(s) = \sigma(t)$ in the free algebra (i.e., syntactic equality). E-unification generalizes this to equational theories.

### 2.25 Unification in the Presence of Type Constructors with Variance

When type constructors have variance (covariant, contravariant, or invariant), unification must respect the variance.

**Definition 2.63 (Variance).** A type constructor $F$ has variance:
- **Covariant** in position $i$ if $A \leq B$ implies $F(\ldots, A, \ldots) \leq F(\ldots, B, \ldots)$.
- **Contravariant** if $A \leq B$ implies $F(\ldots, B, \ldots) \leq F(\ldots, A, \ldots)$.
- **Invariant** if neither holds.

For standard unification (without subtyping), variance is irrelevant: we always require exact equality. But when combining unification with subtyping (as in some OO languages), variance affects the constraint-solving process.

**Example 2.64.** The function type constructor $\to$ is contravariant in its first argument and covariant in its second:

$$A_1 \to B_1 \leq A_2 \to B_2 \quad \text{iff} \quad A_2 \leq A_1 \text{ and } B_1 \leq B_2$$

If we have the constraint $\alpha \to \text{Int} \leq \text{Bool} \to \beta$, we get $\text{Bool} \leq \alpha$ (contravariant) and $\text{Int} \leq \beta$ (covariant). With subtyping, these are inequality constraints, not equality constraints, and require a different solving strategy.

### 2.26 Unification and Anti-Unification

**Definition 2.65 (Anti-Unification / Generalization).** Given two terms $s$ and $t$, the anti-unification (or least general generalization) is a term $g$ such that:
- There exist substitutions $\sigma_1, \sigma_2$ with $\sigma_1(g) = s$ and $\sigma_2(g) = t$.
- $g$ is the most specific (least general) such term.

Anti-unification is the dual of unification: while unification finds the most general common instance, anti-unification finds the most specific common generalization.

**Example 2.66.** Anti-unify $\text{Int} \to \text{Int}$ and $\text{Bool} \to \text{Bool}$:
- Result: $\alpha \to \alpha$ (with $\sigma_1 = [\alpha \mapsto \text{Int}]$ and $\sigma_2 = [\alpha \mapsto \text{Bool}]$).

Anti-unify $\text{Int} \to \text{Bool}$ and $\text{Bool} \to \text{Int}$:
- Result: $\alpha \to \beta$ (the arguments differ independently).

**Theorem 2.67 (Plotkin 1970).** First-order anti-unification always has a unique least general generalization (up to renaming), and it can be computed in linear time.

Anti-unification is used in:
- **Inductive logic programming** to generalize from examples.
- **Clone detection** to find similar code fragments.
- **Type error diagnosis** to suggest the "intended" type when two incompatible types are found.

## Summary

1. **Unification** is the problem of finding a substitution that makes two terms syntactically equal. It is the computational engine of type inference.

2. **Robinson's algorithm** solves unification by recursive case analysis: decompose compound terms, eliminate variables, and check for occurs violations. It always terminates and produces a most general unifier when one exists.

3. **The most general unifier (MGU)** exists whenever a unifier exists, and is unique up to variable renaming. Every other unifier is an instance of the MGU.

4. **The occurs check** prevents infinite types by ensuring that a variable does not appear in the term it is being unified with. Omitting it leads to unsoundness or non-termination.

5. **Complexity:** The naive algorithm is exponential due to term duplication, but union-find optimizations achieve nearly linear time $O(n \cdot \alpha(n))$.

6. **The Martelli--Montanari formulation** presents unification as a confluent, terminating rewrite system on equation sets, providing an elegant correctness argument.

7. **Combining constraint generation with unification** yields a complete type inference algorithm for the STLC that produces principal types.

8. **Higher-order unification** is undecidable in general, but the pattern fragment (Miller 1991) is decidable and suffices for most practical applications in dependently typed languages.
