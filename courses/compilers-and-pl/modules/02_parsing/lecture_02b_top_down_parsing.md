## 1. Recursive Descent Parsing

### 1.1 Overview

A *recursive descent parser* is a top-down parser built from a set of mutually recursive procedures, one for each nonterminal in the grammar. Each procedure recognizes the language generated by its nonterminal.

### 1.2 Structure

For a grammar with nonterminals $A_1, \ldots, A_k$, the parser has:
- One function per nonterminal: `parse_A1()`, `parse_A2()`, etc.
- Each function examines the current lookahead token and chooses a production to apply.
- Terminals are matched by consuming the current token and advancing the input.

```
function parse_A():
    // A -> alpha_1 | alpha_2 | ... | alpha_n
    switch lookahead:
        case tokens predicting alpha_1:
            parse alpha_1
        case tokens predicting alpha_2:
            parse alpha_2
        ...
        default:
            error("unexpected token")
```

### 1.3 Example

Grammar (after left-factoring and left-recursion elimination):

$$E \to T\, E'$$
$$E' \to +\, T\, E' \mid \varepsilon$$
$$T \to F\, T'$$
$$T' \to *\, F\, T' \mid \varepsilon$$
$$F \to (\, E\, ) \mid \mathbf{id}$$

```
function parse_E():
    parse_T()
    parse_E_prime()

function parse_E_prime():
    if lookahead == '+':
        match('+')
        parse_T()
        parse_E_prime()
    else:
        // epsilon production: do nothing

function parse_T():
    parse_F()
    parse_T_prime()

function parse_T_prime():
    if lookahead == '*':
        match('*')
        parse_F()
        parse_T_prime()
    else:
        // epsilon production

function parse_F():
    if lookahead == '(':
        match('(')
        parse_E()
        match(')')
    elif lookahead == ID:
        match(ID)
    else:
        error("expected '(' or identifier")

function match(expected):
    if lookahead == expected:
        lookahead = next_token()
    else:
        error("expected " + expected)
```

## 2. Predictive Parsing

### 2.1 Requirements

For recursive descent to work without backtracking (i.e., *predictive parsing*), the parser must be able to determine which production to use based on a bounded amount of lookahead. This leads to the LL parsing framework.

### 2.2 LL(k) Parsing

**Definition 2.1.** A grammar is *LL(k)* if, for every pair of leftmost derivations:

$$S \Rightarrow_{lm}^* wA\alpha \Rightarrow_{lm} w\beta\alpha \Rightarrow_{lm}^* wx$$
$$S \Rightarrow_{lm}^* wA\alpha \Rightarrow_{lm} w\gamma\alpha \Rightarrow_{lm}^* wy$$

if the first $k$ symbols of $x$ equal the first $k$ symbols of $y$, then $\beta = \gamma$.

In other words, the first $k$ tokens of remaining input uniquely determine the production to apply. "LL" stands for "Left-to-right scan, Leftmost derivation."

---

## 3. FIRST and FOLLOW Sets

### 3.1 FIRST Sets

**Definition 3.1.** For $\alpha \in (V \cup T)^*$:

$$\text{FIRST}(\alpha) = \{a \in T \mid \alpha \Rightarrow^* a\beta \text{ for some } \beta\} \cup (\text{if } \alpha \Rightarrow^* \varepsilon \text{ then } \{\varepsilon\} \text{ else } \emptyset)$$

**Algorithm for computing FIRST:**

```
function ComputeFIRST(Grammar G):
    // Initialize
    for each terminal a:
        FIRST(a) = {a}
    for each nonterminal A:
        FIRST(A) = {}

    repeat until no changes:
        for each production A -> X_1 X_2 ... X_k:
            for i = 1 to k:
                // Add FIRST(X_i) \ {epsilon} to FIRST(A)
                FIRST(A) = FIRST(A) union (FIRST(X_i) \ {epsilon})
                if epsilon not in FIRST(X_i):
                    break
                if i == k:
                    // All X_1, ..., X_k can derive epsilon
                    FIRST(A) = FIRST(A) union {epsilon}
        for each production A -> epsilon:
            FIRST(A) = FIRST(A) union {epsilon}

    return FIRST
```

**Extending FIRST to strings:** For $\alpha = X_1 X_2 \cdots X_k$:

$$\text{FIRST}(X_1 X_2 \cdots X_k) = \begin{cases} \text{FIRST}(X_1) \setminus \{\varepsilon\} \cup \text{FIRST}(X_2 \cdots X_k) & \text{if } \varepsilon \in \text{FIRST}(X_1) \\ \text{FIRST}(X_1) & \text{otherwise} \end{cases}$$

### 3.2 FOLLOW Sets

**Definition 3.2.** For nonterminal $A \in V$:

$$\text{FOLLOW}(A) = \{a \in T \mid S \Rightarrow^* \alpha A a \beta \text{ for some } \alpha, \beta\}$$

If $A$ can appear at the end of a sentential form, then $\$ \in \text{FOLLOW}(A)$ (where $\$$ is the end-of-input marker).

**Algorithm for computing FOLLOW:**

```
function ComputeFOLLOW(Grammar G):
    FOLLOW(S) = {$}
    for each other nonterminal A:
        FOLLOW(A) = {}

    repeat until no changes:
        for each production A -> alpha_1 B alpha_2:
            // Rule 1: FIRST(alpha_2) \ {epsilon} goes into FOLLOW(B)
            FOLLOW(B) = FOLLOW(B) union (FIRST(alpha_2) \ {epsilon})

            // Rule 2: if alpha_2 =>* epsilon, then FOLLOW(A) goes into FOLLOW(B)
            if epsilon in FIRST(alpha_2) or alpha_2 == epsilon:
                FOLLOW(B) = FOLLOW(B) union FOLLOW(A)

    return FOLLOW
```

### 3.3 Correctness

**Theorem 3.3.** The FIRST and FOLLOW algorithms compute fixed points of monotone functions on the lattice $(\mathcal{P}(T \cup \{\varepsilon, \$\}), \subseteq)$. By the Kleene fixed-point theorem (Lecture 00b), they converge to the least fixed point, which corresponds to the correct FIRST and FOLLOW sets.

*Proof.* Each iteration of the algorithm adds elements to FIRST/FOLLOW sets but never removes them. The sets are bounded (subsets of $T \cup \{\varepsilon\}$ or $T \cup \{\$\}$). Hence the algorithm terminates in at most $|T| \cdot |V|$ iterations. Correctness follows from the characterization of FIRST and FOLLOW as least fixed points of the defining equations. $\blacksquare$

## 4. LL(1) Grammars

### 4.1 Definition

**Definition 4.1.** A grammar $G$ is *LL(1)* if for every nonterminal $A$ with productions $A \to \alpha_1 \mid \alpha_2 \mid \cdots \mid \alpha_n$:

1. $\text{FIRST}(\alpha_i) \cap \text{FIRST}(\alpha_j) = \emptyset$ for all $i \neq j$.
2. If $\varepsilon \in \text{FIRST}(\alpha_i)$, then $\text{FIRST}(\alpha_j) \cap \text{FOLLOW}(A) = \emptyset$ for all $j \neq i$.

Equivalently, for all pairs $A \to \alpha$ and $A \to \beta$ with $\alpha \neq \beta$:

$$\text{PREDICT}(A \to \alpha) \cap \text{PREDICT}(A \to \beta) = \emptyset$$

where:

$$\text{PREDICT}(A \to \alpha) = \begin{cases} (\text{FIRST}(\alpha) \setminus \{\varepsilon\}) \cup \text{FOLLOW}(A) & \text{if } \varepsilon \in \text{FIRST}(\alpha) \\ \text{FIRST}(\alpha) & \text{otherwise} \end{cases}$$

### 4.2 LL(1) Parse Table Construction

**Algorithm:**

```
function BuildLL1Table(Grammar G):
    for each production A -> alpha:
        for each terminal a in FIRST(alpha):
            Table[A, a] = A -> alpha
        if epsilon in FIRST(alpha):
            for each terminal b in FOLLOW(A):
                Table[A, b] = A -> alpha
            if $ in FOLLOW(A):
                Table[A, $] = A -> alpha

    // If any Table[A, a] has multiple entries, G is not LL(1)
    return Table
```

### 4.3 Table-Driven LL(1) Parser

```
function LL1Parse(Table, input w$):
    stack = [S, $]
    pointer = first symbol of w$

    while stack is not empty:
        X = top of stack
        a = current input symbol (pointed to by pointer)

        if X == a:
            pop stack
            advance pointer
        elif X is a terminal:
            error("expected " + X + ", got " + a)
        elif Table[X, a] is empty:
            error("unexpected " + a)
        else:
            // Table[X, a] = X -> Y_1 Y_2 ... Y_k
            pop X from stack
            push Y_k, ..., Y_2, Y_1 onto stack  // Y_1 on top

    if pointer == $:
        accept
    else:
        error("trailing input")
```

### 4.4 Properties of LL(1) Grammars

**Theorem 4.2.** If $G$ is LL(1), then:

1. $G$ is unambiguous.
2. $G$ has no left recursion (neither direct nor indirect).
3. $G$ is left-factored.

*Proof of (1).* If $G$ were ambiguous, some string $w$ would have two distinct leftmost derivations. At the first point of divergence, two different productions $A \to \alpha$ and $A \to \beta$ are applied with the same next input symbol $a$. This means $a \in \text{PREDICT}(A \to \alpha) \cap \text{PREDICT}(A \to \beta)$, contradicting LL(1). $\blacksquare$

*Proof of (2).* If $A \Rightarrow^+ A\alpha$, then $A$ has a production $A \to A\gamma$ (or indirect left recursion). For any $a \in \text{FIRST}(A\gamma)$, we have $a \in \text{PREDICT}(A \to A\gamma)$. But $a$ must also be in $\text{PREDICT}$ for whatever production starts the derivation of $A$ (since $A$ derives strings starting with $a$). This creates a conflict. $\blacksquare$

## 5. LL(k) and Strong LL(k)

### 5.1 LL(k) vs Strong LL(k)

**Definition 5.1.** A grammar is *strong LL(k)* if the production choice for nonterminal $A$ depends only on the next $k$ input symbols, regardless of the left context. A grammar is *LL(k)* if the choice may also depend on the left context (what has been derived so far).

For $k = 1$, LL(1) and strong LL(1) coincide.

**Theorem 5.2.** For $k \geq 2$, strong LL(k) $\subsetneq$ LL(k).

### 5.2 Practical Relevance

Most practical top-down parsers use LL(1) with strategic modifications:
- **LL(1) with conflict resolution:** When conflicts arise, resolve by examining additional context.
- **LL(*) (ANTLR):** Use arbitrary lookahead, decided at parse time.
- **Backtracking:** Try alternatives in order; backtrack on failure.

## 6. Limitations of Top-Down Parsing

### 6.1 Languages Not LL(k)

**Theorem 6.1.** No left-recursive grammar is LL(k) for any $k$.

**Theorem 6.2.** There exist deterministic CFLs that are not LL(k) for any $k$.

**Example.** $L = \{a^n b c^n \mid n \geq 1\} \cup \{a^n d c^{2n} \mid n \geq 1\}$. To distinguish whether to expect $c^n$ or $c^{2n}$, the parser must remember whether it saw $b$ or $d$, which was preceded by $a^n$. No finite lookahead at the start suffices.

### 6.2 Grammars Requiring Transformation

Many natural grammars are not LL(1) but can be made so:

- **Left recursion:** Eliminate via the standard transformation (Section 4 of Lecture 02a).
- **Common prefixes:** Left-factor.
- **Dangling else:** Resolve by precedence (prefer shifting / matching nearest `if`).

However, these transformations change the parse tree structure, requiring additional work to build the desired AST.

## 7. Packrat Parsing and PEGs

### 7.1 Parsing Expression Grammars (Ford, 2004)

**Definition 7.1 (PEG).** A *parsing expression grammar* is a 4-tuple $G = (V, T, P, e_S)$ where $P$ maps each nonterminal to a *parsing expression*. Parsing expressions are defined inductively:

| Expression | Meaning |
|-----------|---------|
| $\varepsilon$ | Always succeeds, consumes nothing |
| $a$ (terminal) | Matches $a$ and consumes it |
| $A$ (nonterminal) | Invokes rule for $A$ |
| $e_1\, e_2$ | Sequence: match $e_1$ then $e_2$ |
| $e_1\, /\, e_2$ | Ordered choice: try $e_1$; if it fails, try $e_2$ |
| $e^*$ | Zero or more repetitions of $e$ |
| $!e$ | Negative lookahead: succeeds iff $e$ fails; consumes nothing |

**Key difference from CFGs:** The ordered choice $e_1 / e_2$ is *deterministic*: if $e_1$ succeeds, $e_2$ is never tried. This eliminates ambiguity by construction.

### 7.2 PEGs vs CFGs

**Theorem 7.2 (Ford, 2004).** Every LL(k) language can be expressed as a PEG. It is an open problem whether all CFLs can be expressed as PEGs.

PEGs can express some non-context-free languages. For example, $\{a^n b^n c^n \mid n \geq 1\}$ has a PEG using the `!` operator for lookahead.

### 7.3 Packrat Parsing

**Definition 7.3.** A *packrat parser* is a top-down parser for PEGs that memoizes every parsing function call. This guarantees $O(n)$ parsing time (where $n$ is the input length) at the cost of $O(n \cdot |V|)$ space.

**Algorithm:**

```
memo = {} // maps (nonterminal, position) -> (result, new_position) or FAIL

function parse(nonterminal A, position pos):
    if (A, pos) in memo:
        return memo[(A, pos)]

    result = evaluate parsing expression P[A] at position pos
    memo[(A, pos)] = result
    return result
```

### 7.4 Complexity

**Theorem 7.4.** Packrat parsing runs in $O(n \cdot |G|)$ time and $O(n \cdot |V|)$ space.

*Proof.* There are $|V| \cdot (n + 1)$ possible memo entries. Each entry is computed at most once. Evaluating a parsing expression takes $O(|G|)$ time in the worst case per entry (for sequence and choice). Total: $O(n \cdot |V| \cdot |G|) = O(n \cdot |G|^2)$, or $O(n \cdot |G|)$ with careful analysis. $\blacksquare$

### 7.5 Practical Considerations

**Advantages of PEGs/packrat:**
- No ambiguity by construction.
- Easy to write and understand.
- Guaranteed linear-time parsing.
- Handle unlimited lookahead naturally.

**Disadvantages:**
- Ordered choice can be confusing: $a / ab$ matches only $a$ (never $ab$).
- No left recursion (packrat parsing loops). Extensions exist (Warth et al., 2008).
- Memory consumption: $O(n \cdot |V|)$ can be significant.
- Error reporting is challenging (failures are silently backtracked).

### 7.6 PEG Implementations

- **ANTLR 4** uses an LL(*) strategy inspired by PEGs (adaptive LL(*)): it tries alternatives using prediction automata and falls back to full LL parsing.
- **PEG.js / Ohm / pest (Rust):** PEG-based parser generators.
- **Tree-sitter:** Uses a GLR parser but with PEG-like error recovery.

## 8. Error Handling in Top-Down Parsers

### 8.1 Panic Mode

When the current token does not match any production:

1. Pop nonterminals from the stack until reaching one whose FOLLOW set contains the current token (or a *synchronizing token* like `;`, `}`, etc.).
2. Discard input tokens until finding one in the FOLLOW set of the popped nonterminal.
3. Resume parsing.

### 8.2 Error Productions

Add grammar productions that explicitly match common errors:

```
stmt -> IF LPAREN expr RPAREN stmt          // correct
     |  IF expr RPAREN stmt                 // missing LPAREN
     |  IF LPAREN expr stmt                 // missing RPAREN
```

This pollutes the grammar but produces excellent error messages.

### 8.3 Recursive Descent Error Recovery

In hand-written parsers, error recovery is more flexible:

```
function parse_stmt():
    if lookahead == IF:
        match(IF)
        if lookahead != LPAREN:
            error("missing '(' after 'if'")
        else:
            match(LPAREN)
        parse_expr()
        if lookahead != RPAREN:
            error("missing ')' after condition")
            // Don't consume -- try to continue
        else:
            match(RPAREN)
        parse_stmt()
```

## 9. Summary

| Parser Type | Grammar Class | Lookahead | Time | Space | Backtracking |
|------------|--------------|-----------|------|-------|-------------|
| Recursive descent | LL(1) | 1 token | $O(n)$ | $O(n)$ stack | No |
| LL(k) table-driven | LL(k) | $k$ tokens | $O(n)$ | $O(n)$ | No |
| LL(*) (ANTLR) | LL-regular | Adaptive | $O(n)$ typical | $O(n)$ | Selective |
| Packrat (PEG) | PEG | Unlimited | $O(n)$ | $O(n \cdot \lvert V \rvert)$ | Memoized |
| Backtracking | Any CFG | Unlimited | Exponential worst case | $O(n)$ | Yes |
