## 1. Learning Objectives

By the end of this lecture, you will be able to:

1. **Apply** structural induction to prove properties of recursive functions over datatypes.
2. **Define** recursive functions using `fun`, `primrec`, and `function` and explain the differences.
3. **Prove** termination for recursive functions, both automatically and manually.
4. **Use** rule induction for inductively defined predicates and relations.
5. **Apply** well-founded induction in HOL for non-structural recursion patterns.

## 2. Structural Induction

### 2.1 Induction Principles from Datatypes

Every `datatype` declaration automatically generates a structural induction principle. For lists:

```isabelle
datatype 'a list = Nil | Cons 'a "'a list"

thm list.induct:
  "\<lbrakk> P Nil; \<And>x xs. P xs \<Longrightarrow> P (Cons x xs) \<rbrakk> \<Longrightarrow> P ys"
```

For binary trees:

```isabelle
datatype 'a tree = Leaf | Node "'a tree" 'a "'a tree"

thm tree.induct:
  "\<lbrakk> P Leaf;
     \<And>l x r. \<lbrakk> P l; P r \<rbrakk> \<Longrightarrow> P (Node l x r) \<rbrakk>
   \<Longrightarrow> P t"
```

### 2.2 Using Induction in Proofs

The `induct` proof method applies structural induction:

```isabelle
lemma append_assoc: "append (append xs ys) zs = append xs (append ys zs)"
proof (induct xs)
  case Nil
  then show ?case by simp
next
  case (Cons x xs)
  then show ?case by simp
qed
```

The shorter form:

```isabelle
lemma append_assoc: "append (append xs ys) zs = append xs (append ys zs)"
  by (induct xs) auto
```

### 2.3 Induction with Arbitrary Variables

When the induction hypothesis needs to hold for *all* values of some variable, use `arbitrary`:

```isabelle
lemma rev_append: "rev_acc acc xs = append (rev xs) acc"
  by (induct xs arbitrary: acc) auto
```

Without `arbitrary: acc`, the induction hypothesis would be fixed to a specific `acc`, making the inductive step unprovable.

### 2.4 Computation Induction

For functions defined by `fun`, Isabelle generates a *computation induction* rule that follows the recursion pattern:

```isabelle
fun fib :: "nat => nat" where
  "fib 0 = 0"
| "fib (Suc 0) = 1"
| "fib (Suc (Suc n)) = fib n + fib (Suc n)"

thm fib.induct:
  "\<lbrakk> P 0; P (Suc 0); \<And>n. P n \<Longrightarrow> P (Suc n) \<Longrightarrow> P (Suc (Suc n)) \<rbrakk>
   \<Longrightarrow> P m"
```

This is stronger than natural number induction because it provides two induction hypotheses in the step case.

## 3. Defining Recursive Functions

### 3.1 The fun Command

`fun` is the primary command for defining recursive functions. It handles:

- Pattern matching across multiple equations.
- Automatic termination proofs via lexicographic orderings.
- Generation of simplification rules and induction principles.

```isabelle
fun flatten :: "'a tree => 'a list" where
  "flatten Leaf = []"
| "flatten (Node l x r) = flatten l @ [x] @ flatten r"
```

After this definition, Isabelle provides:

```isabelle
thm flatten.simps:  -- the defining equations as simp rules
thm flatten.induct: -- computation induction
```

### 3.2 The primrec Command

`primrec` defines *primitive recursive* functions. These always terminate because recursion is restricted to the immediate predecessor in the datatype:

```isabelle
primrec length :: "'a list => nat" where
  "length [] = 0"
| "length (x # xs) = Suc (length xs)"
```

Restrictions of `primrec`:
- Exactly one equation per constructor.
- The recursive call must be on a direct subterm of the constructor pattern.
- No nested or mutual recursion (use `fun` instead).

The advantage: `primrec` never requires a termination proof.

### 3.3 The function Command

`function` is the most general command, for functions where automatic termination proofs fail:

```isabelle
function gcd :: "nat => nat => nat" where
  "gcd m 0 = m"
| "gcd 0 n = n"
| "gcd (Suc m) (Suc n) = (if m < n then gcd (Suc m) (n - m)
                           else gcd (m - n) (Suc n))"
by pat_completeness auto
termination
  by (relation "measure (\<lambda>(m, n). m + n)") auto
```

The workflow with `function`:

1. **Define** the function with equations.
2. **Prove pattern completeness:** all cases are covered (usually `by pat_completeness auto`).
3. **Prove termination:** provide a well-founded relation and show the arguments decrease.

Until termination is proved, the function's simplification rules are conditional (guarded by `dom` predicates).

## 4. Termination Proofs

### 4.1 Automatic Termination

`fun` attempts automatic termination using *lexicographic orderings* on the arguments. It measures each argument by:

- **Size:** the `size` function generated by the datatype package.
- **Subterm relation:** direct subterm ordering.

For most simple recursive functions, this succeeds automatically.

### 4.2 Manual Termination

When automatic termination fails, provide the relation explicitly:

```isabelle
function collatz :: "nat => nat list" where
  "collatz 0 = [0]"
| "collatz (Suc 0) = [1]"
| "collatz n = n # (if even n then collatz (n div 2) else collatz (3 * n + 1))"
by pat_completeness auto
termination
  sorry  -- termination of Collatz is a famous open problem!
```

For functions with provable termination:

```isabelle
function log2 :: "nat => nat" where
  "log2 0 = 0"
| "log2 (Suc 0) = 0"
| "log2 n = Suc (log2 (n div 2))"
by pat_completeness auto
termination
  by (relation "measure id") auto
```

### 4.3 Well-Founded Relations

A relation $R$ on a type $\alpha$ is *well-founded* if there are no infinite descending chains $a_0 \mathrel{R} a_1 \mathrel{R} a_2 \mathrel{R} \cdots$. Termination of a recursive function is proved by finding a well-founded relation such that every recursive call decreases the argument:

```isabelle
definition wf :: "('a * 'a) set => bool" where
  "wf R \<longleftrightarrow> (\<forall>P. (\<forall>x. (\<forall>y. (y, x) \<in> R \<longrightarrow> P y) \<longrightarrow> P x) \<longrightarrow> (\<forall>x. P x))"
```

Common well-founded relations:

| Relation | Syntax | Description |
|---|---|---|
| Natural number `<` | `measure f` | $f(x) < f(y)$ for naturals |
| Lexicographic | `measures [f1, f2, ...]` | Lexicographic on multiple measures |
| Inverse image | `inv_image R f` | $R$ on images under $f$ |
| Subset | `finite_psubset` | Strict subset on finite sets |

## 5. Inductively Defined Predicates

### 5.1 The inductive Command

Isabelle's `inductive` command defines predicates (relations) by their introduction rules:

```isabelle
inductive even :: "nat => bool" where
  zero: "even 0"
| step: "even n ==> even (Suc (Suc n))"
```

This generates:

- **Introduction rules:** `even.zero` and `even.step`.
- **Elimination (case analysis):** `even.cases`.
- **Induction (rule induction):** `even.induct`.
- **A monotonicity witness** for the underlying fixed-point construction.

### 5.2 Rule Induction

Rule induction is the induction principle for inductively defined predicates. For `even`:

```isabelle
thm even.induct:
  "\<lbrakk> even n; P 0; \<And>n. \<lbrakk> even n; P n \<rbrakk> \<Longrightarrow> P (Suc (Suc n)) \<rbrakk>
   \<Longrightarrow> P n"
```

Note the key difference from structural induction on `nat`: rule induction provides the *assumption* `even n` in the induction hypothesis. This is stronger because it restricts to even numbers.

**Example:**

```isabelle
lemma even_double: "even n ==> \<exists>k. n = 2 * k"
proof (induction n rule: even.induct)
  case zero
  then show ?case by auto
next
  case (step n)
  then obtain k where "n = 2 * k" by auto
  then have "Suc (Suc n) = 2 * (k + 1)" by auto
  then show ?case by auto
qed
```

### 5.3 Inductive Relations

Relations are defined similarly:

```isabelle
inductive big_step :: "com * state => state => bool"
  (infix "\<Rightarrow>" 55) where
  Skip: "(SKIP, s) \<Rightarrow> s"
| Assign: "(x ::= a, s) \<Rightarrow> s(x := aval a s)"
| Seq: "\<lbrakk> (c1, s1) \<Rightarrow> s2; (c2, s2) \<Rightarrow> s3 \<rbrakk>
        \<Longrightarrow> (c1;; c2, s1) \<Rightarrow> s3"
| IfTrue: "\<lbrakk> bval b s; (c1, s) \<Rightarrow> t \<rbrakk>
           \<Longrightarrow> (IF b THEN c1 ELSE c2, s) \<Rightarrow> t"
| IfFalse: "\<lbrakk> \<not>bval b s; (c2, s) \<Rightarrow> t \<rbrakk>
            \<Longrightarrow> (IF b THEN c1 ELSE c2, s) \<Rightarrow> t"
| WhileFalse: "\<not>bval b s \<Longrightarrow> (WHILE b DO c, s) \<Rightarrow> s"
| WhileTrue: "\<lbrakk> bval b s; (c, s) \<Rightarrow> s'; (WHILE b DO c, s') \<Rightarrow> t \<rbrakk>
              \<Longrightarrow> (WHILE b DO c, s) \<Rightarrow> t"
```

This defines the big-step operational semantics of the IMP language (covered in detail in Module 08).

## 6. Well-Founded Induction in HOL

### 6.1 The General Principle

Well-founded induction generalizes structural induction to arbitrary well-founded relations:

```isabelle
theorem wf_induct:
  "\<lbrakk> wf R; \<And>x. (\<forall>y. (y, x) \<in> R \<Longrightarrow> P y) \<Longrightarrow> P x \<rbrakk>
   \<Longrightarrow> P a"
```

This says: to prove $P(a)$ for all $a$, it suffices to show that $P(x)$ holds assuming $P(y)$ for all $y$ strictly smaller than $x$ in the relation $R$.

### 6.2 Example: Strong Induction on Naturals

Strong (complete) induction on naturals is a special case of well-founded induction with $R = {<}$:

```isabelle
lemma strong_induct:
  "(\<And>n::nat. (\<forall>m < n. P m) \<Longrightarrow> P n) \<Longrightarrow> P k"
  by (rule wf_induct[OF wf_less])
```

### 6.3 Application: Division Algorithm

```isabelle
lemma div_exists:
  fixes a b :: nat
  assumes "b > 0"
  shows "\<exists>q r. a = b * q + r \<and> r < b"
using assms
proof (induction a rule: less_induct)
  case (less a)
  show ?case
  proof (cases "a < b")
    case True
    then show ?thesis by (intro exI[of _ 0] exI[of _ a]) auto
  next
    case False
    then have "a - b < a" using less.prems by auto
    then obtain q r where "a - b = b * q + r" "r < b"
      using less.IH less.prems by auto
    then have "a = b * (q + 1) + r" using False by auto
    then show ?thesis using \<open>r < b\<close> by blast
  qed
qed
```

## 7. Mutual Recursion

### 7.1 Mutually Recursive Functions

For mutually recursive datatypes, use simultaneous `fun`:

```isabelle
datatype
  expr = Const int | Add expr expr | Neg expr
and
  stmt = Assign string expr | Seq stmt stmt | Skip

fun eval_expr :: "expr => (string => int) => int"
and eval_stmt :: "stmt => (string => int) => (string => int)" where
  "eval_expr (Const n) _ = n"
| "eval_expr (Add e1 e2) env = eval_expr e1 env + eval_expr e2 env"
| "eval_expr (Neg e) env = - eval_expr e env"
| "eval_stmt (Assign x e) env = env(x := eval_expr e env)"
| "eval_stmt (Seq s1 s2) env = eval_stmt s2 (eval_stmt s1 env)"
| "eval_stmt Skip env = env"
```

### 7.2 Mutual Induction

The mutual datatype generates a combined induction principle:

```isabelle
thm expr_stmt.induct:
  "\<lbrakk> \<And>i. P1 (Const i);
     \<And>e1 e2. P1 e1 \<Longrightarrow> P1 e2 \<Longrightarrow> P1 (Add e1 e2);
     \<And>e. P1 e \<Longrightarrow> P1 (Neg e);
     \<And>s e. P1 e \<Longrightarrow> P2 (Assign s e);
     \<And>s1 s2. P2 s1 \<Longrightarrow> P2 s2 \<Longrightarrow> P2 (Seq s1 s2);
     P2 Skip \<rbrakk>
   \<Longrightarrow> P1 e \<and> P2 s"
```

## 8. Code Generation

### 8.1 From Proofs to Programs

One of HOL's distinctive features is *code generation*: extracting executable programs from function definitions.

```isabelle
fun mergesort :: "nat list => nat list" where
  "mergesort [] = []"
| "mergesort [x] = [x]"
| "mergesort xs = (let (l, r) = split xs
                   in merge (mergesort l) (mergesort r))"

export_code mergesort in Haskell
export_code mergesort in SML
export_code mergesort in OCaml
export_code mergesort in Scala
```

The generated code is guaranteed correct by construction: every step in the function definition has been verified by Isabelle's kernel.

### 8.2 Refinement

For efficiency, you can *refine* verified algorithms with efficient data structures:

```isabelle
(* Verified algorithm on abstract sets *)
fun my_algorithm :: "'a set => 'a set" where ...

(* Refined implementation using red-black trees *)
lemma my_algorithm_rbt: "my_algorithm (set xs) = set (my_algorithm_impl xs)"
  ...
```

## 9. Key Takeaways

1. Structural induction is automatically generated for datatypes and applied via the `induct` method.
2. `primrec` is for simple primitive recursion (always terminates), `fun` for general recursion with automatic termination, `function` for functions needing manual termination proofs.
3. Rule induction for `inductive` predicates restricts the induction to values satisfying the predicate.
4. Well-founded induction generalizes all induction principles: structural, strong, and custom.
5. The `arbitrary` modifier is essential when the induction hypothesis must be universally quantified.
6. Code generation extracts verified executable programs from HOL function definitions.
